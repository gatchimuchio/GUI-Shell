# B4 製品接続設計

## 目的と状態

B4の最初の施工単位として、既存AgentTaskへ調停結果を接続する前提となる実行識別子とsource revisionの表現を確定する。本書は契約適合の設計記録であり、まだ製品Runtime consumer、UI投影、B4完了を意味しない。

状態: 実装中。B4はOPEN。

## 現行実装で観測した事実

- Desktop Brokerは`native/rust_helper/src/broker/ipc_server.rs`で`broker-session-`と128-bit乱数からsession IDを生成し、その値を`Broker::new_persistent`へ渡す。要求envelopeはBrokerのsession IDと一致しなければ実行されない。
- `AgentTask作業`はTask、Runtime、Session、Workspace、Workspace実体、指示hashをBroker内で保持する。Task実行要求からsource commitは受け取らず、製品経路にGit依存を足す契約もない。
- Host CenterのHost切替はmetadata表示contextの選択であり、Task実行先Hostを切り替えず、Task Permission／Approvalも作らない。選択Host IDをAgentTaskの実行Hostとして流用しない。
- `WorkspaceTaskScratch`の実作用と後始末はCodex Adapter内で成立するが、その結果をBrokerのTask記録、durable Audit、Agent Centerへ返すconsumerはまだない。

## 契約修正

`specs/buffer_intervention_record.schema.json`をv2とする。

- `実行HostID`は、当該Taskを実際に受け付けたBroker session IDをBroker自身が設定する。`実行Host識別方式=broker_session_id`を必須にし、Adapter metadataやHost Centerの表示選択から設定しない。このIDは実行Broker境界の識別子であり、物理machineの恒久identityを主張しない。
- source commitは取得できた場合だけ40桁commitとして記録する。Git非依存のWorkspaceで取得経路がない場合は`取得状態=未取得`、commit=null、理由=`取得経路なし`と明記する。欠落値、ゼロhash、現行RepositoryのHEADで代用しない。
- source commitが未取得の記録は、実作用の記録に使えても`吸収成立`にはできない。`作用後未照合`や`未観測`の範囲にとどめ、独立した同条件確認が別途成立するまで成功主張へ昇格しない。
- `Host指紋hash`はBroker session IDのhashとして扱い、Host物理特性の測定値と誤認しない。`Workspace登録hash`はWorkspaceの登録束縛だけを表し、Workspace内容全体のsnapshotとは主張しない。

## Authority・露出境界

この記録はBrokerが作る非権限の結果投影であり、Permission、Approval、Capability、Trust、Recovery可否を生成しない。Task／Workspaceの束縛と一回Permission・Approval消費は既存Broker経路だけが決める。記録やAdapter metadataの不一致、source/Host識別不能、Audit保存失敗は緩衝成功へ読み替えない。

## 次の実装対象

1. Codex AdapterからTask scratchの適用・cleanup結果を型付きでBrokerへ返す。
2. BrokerがTask ID、Broker session ID、Workspace登録、指示hash、Toolchain fingerprintを現行Taskと再照合して記録を構築する。
3. Task終端Auditへrecord hashと状態を結合し、Agent Centerへboundedな非本文projectionを返す。
4. mismatched Task／Workspace／Host、Adapter metadata escalation、Audit unavailableを拒否する。

この次工程が終わるまでB4はCLOSEDにしない。`task_execution=unsupported`、`release_ready=false`は変更しない。
